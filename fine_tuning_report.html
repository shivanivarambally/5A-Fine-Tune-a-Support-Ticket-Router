Support Ticket Router Fine-Tuning Report

A record of the two Qwen3 LoRA fine-tuning iterations, their baseline comparisons, observed validation metrics, and the final conclusion.

Executive conclusion: Fine-tuning was successful. The latest model reached 70.7% validation accuracy versus 31.6% for its base model, a gain of 39.1 percentage points. The second run is more balanced by macro F1, but the two fine-tuned accuracies were measured on different validation splits.

1. What Was Done

  1. Prepared labeled support-ticket data in ShareGPT format.
  2. Split the data into stratified training and validation sets.
  3. Fine-tuned Qwen/Qwen3-1.7B-Base with a LoRA adapter through LLaMA Factory.
  4. Reviewed the training loss curve.
  5. Measured the base model and fine-tuned model on held-out validation tickets.
  6. Inspected the classification report, confusion matrix, and baseline comparison chart.

6. Final Conclusion

  • Both fine-tuning iterations clearly outperformed their corresponding base models.
  • Iteration 1 had higher measured accuracy, 72.6% versus 70.7%, but the validation sets differed.
  • Iteration 2 had the better macro F1, 0.710 versus 0.679, indicating more balanced category performance.
  • The latest model is a successful prototype, not yet a fully autonomous production router.
  • The next priority is improving Computer-Services and Software classification, then evaluating both models on the same fixed test set.
Recommended next step: Freeze one stratified test split, evaluate both saved models on that identical split, and use the same explicit label order in every report and chart. This will provide a fair final comparison.
